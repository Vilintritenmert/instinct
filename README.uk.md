# instinct

[English](README.md) · **Українська**

Перевіряйте скіли й плагіни агентів перед встановленням. instinct — плагін для Claude Code з одним
скілом, **how-deep-the-rabbit-hole-goes**, який поєднує статичний сканер із перевіркою інструкцій,
коду та конфігурації цілі агентом.

**Статус:** експериментальний · версія пакета **0.11.0** · [MIT](LICENSE)

> [!WARNING]
> Це допоміжний інструмент для аудиту безпеки. Знахідки й коди виходу сканера — сигнали, а не
> вердикти безпечності. Потрібна ручна перевірка; чистий результат не гарантує безпеки.
> Дивіться [обмеження](#обмеження).

## Швидкий старт

Потрібні [Claude Code](https://code.claude.com/docs/en/overview) із підтримкою плагінів та
[PowerShell 7+](https://learn.microsoft.com/powershell/scripting/install/installing-powershell),
доступний як `pwsh`, для сканера.

Виконайте в терміналі:

```bash
claude plugin marketplace add Vilintritenmert/instinct
claude plugin install instinct@instinct
claude
```

У новій сесії Claude Code попросіть:

```text
Перевір скіл у ../candidate-skill на безпечність перед встановленням.
```

Замініть `../candidate-skill` справжнім шляхом до локального скіла чи плагіна. Агент просканує ціль,
перевірить її файли й надасть докази. Ілюстративний початок підсумкового звіту:

```text
Вердикт: REVIEW — не вдалося перевірити архів.
Рекомендація: перевірити вміст архіву перед встановленням.
Покриття: усі текстові файли прочитано; один архів залишається неперевіреним.
```

Скіл, каталог загроз і вивід сканера написано англійською; звіт агент пише мовою користувача.

## Використання

Просіть своїми словами, наприклад:

- «Чи безпечно ставити цей плагін? Перевір ../candidate-plugin».
- «Проведи аудит скілів у ~/.claude/skills».
- "Security-audit the skill in ../candidate-skill."

Аудит сприймає вміст цілі як дані та не встановлює й не виконує його. Агент повідомляє про хід
роботи, одразу попереджає про підтверджені критичні знахідки й дає підсумкову рекомендацію з доказами
за файлами та рядками. Усе, що не вдалося перевірити, залишається явною прогалиною покриття.

### Сканер окремо

Сканер працює й без Claude Code. Маючи Git і PowerShell 7+, клонуйте цей репозиторій та перевірте
тестовий зразок без знахідок:

```bash
git clone https://github.com/Vilintritenmert/instinct.git
cd instinct
pwsh -NoProfile -File ./skills/how-deep-the-rabbit-hole-goes/scripts/scan.ps1 -Path ./tests/how-deep-the-rabbit-hole-goes/clean-skill
```

Кінець виводу:

```text
Summary: CRITICAL 0 · HIGH 0 · MEDIUM 0 · LOW 0
Scan complete: True · coverage gaps: 0
These are signals for manual review, not a verdict.
```

Замініть шлях до зразка шляхом до своєї цілі. Параметр `-Json` дає змогу перевірити `ScanComplete`,
`CoverageIssues`, знахідки та хеші. Код виходу `2` означає сигнал CRITICAL, `1` — HIGH без CRITICAL,
`0` — відсутність обох. Навіть за коду `0` можливі знахідки MEDIUM або неперевірений вміст.
Параметри й контракт виводу описано в [довідці сканера](docs/SCANNER.md) англійською.

### Оновлення та видалення

Щоб оновити маркетплейс і встановлений плагін, виконайте в терміналі:

```bash
claude plugin marketplace update instinct
claude plugin update instinct@instinct
```

Після оновлення почніть нову сесію Claude Code. Повторюйте аудит сторонніх цілей після кожної зміни.
Щоб видалити плагін, встановлений за інструкцією швидкого старту:

```bash
claude plugin uninstall instinct@instinct
```

Для локального маркетплейсу виконайте `claude plugin marketplace add .` із цього репозиторію замість
додавання джерела GitHub. Області встановлення й подробиці команд описано в офіційній
[довідці команд плагінів](https://code.claude.com/docs/en/plugins/cli-reference).

## Результати аудиту

[Каталог загроз](skills/how-deep-the-rabbit-hole-goes/references/threats.md) визначає 26 класів
(T01–T26): перехоплення інструкцій, приховані вказівки, доступ до секретів, ексфільтрацію, віддалене
виконання коду, руйнівні дії, закріплення в системі, автозапуск плагінів, ризики ланцюга постачання
та шкідливий згенерований результат.

Агент підтверджує або відхиляє знахідки сканера під час ручної перевірки, а потім визначає вердикт:

| Вердикт | Значення |
|---|---|
| 🔴 UNSAFE | Підтверджену знахідку CRITICAL або HIGH не виправдовує призначення цілі. |
| 🟡 REVIEW | Знахідки потребують рішення людини або частину вмісту не вдалося перевірити. |
| 🟢 SAFE | Усе перевірено, жодної знахідки вище LOW не підтверджено. Це не гарантія безпеки. |

Самостійний запуск сканера ніколи не видає одного з цих вердиктів аудиту.

## Обмеження

- **Виявлення на зовнішньому наборі залишається обмеженим.** За порогу HIGH+ версія 0.11.0 виявляє
  **1 із 60** текстів із позначкою ін'єкції та сигналізує на **0 із 56** текстів із негативною
  позначкою в зафіксованому публічному тестовому наборі deepset. Позначки не містять початкового
  контексту довіри й рівнів серйозності; набір не вимірює повний аудит скілів. Дивіться
  [довідку оцінювання](tests/how-deep-the-rabbit-hole-goes/EVALUATION.md).
- Окремі набори перефразувань для розробки дають 30/30 і 38/40 виявлень позитивних прикладів та
  0/30 і 1/40 сигналів HIGH+ на контрольних прикладах відповідно. Правила налаштовували на цих
  наборах; результати не доводять точності в реальних умовах. Дивіться
  [перевірку контексту](tests/how-deep-the-rabbit-hole-goes/CONTEXT_REVIEW.md).
- Пошук шаблонів може пропускати нові чи непрямі інструкції та позначати легітимні приклади з
  документації безпеки. Він не встановлює авторизацію, досяжність коду чи потік даних.
- Текстові правила зосереджено на англійській та українській; німецькою покрито лише перехоплення
  інструкцій і розкриття промпту (T01/T06). Інші мови й скрипти поза Python, JavaScript/TypeScript,
  PowerShell і shell потребують особливо уважної ручної перевірки.
- Сканер не аналізує текст у пікселях зображень. Бінарники, архіви й офісні документи позначаються,
  але не відкриваються. Посилання, зокрема кореневі junction, не обходяться. Непідтримувані
  кодування, недоступний вміст і ліміти обробки фіксуються як прогалини покриття.
- Вердикт залежить від версії цілі. Хеші ідентифікують просканований вміст, але файлова система не
  блокується; використовуйте стабільну копію й повторюйте аудит після оновлень.
- Наразі перевірено Windows; валідація на macOS/Linux ще попереду.

## Розробка

Підготовку середовища, домовленості для скілів і потрібні перевірки для різних змін описано в

> `evasion-skill`. Тести читають ці зразки; ніколи не встановлюйте їх і не виконуйте їхні скрипти чи
> хуки. Адреси використовують `example.invalid` і зарезервовані для документації діапазони IP.
> Антивірус може на них зреагувати. Скан самого репозиторію також позначає приклади у сканері та
> документації з безпеки.
